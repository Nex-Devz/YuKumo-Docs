# Security Policy

## Supported Versions

Only the latest release of the documentation site receives security updates.

| Version | Supported          |
| ------- | ------------------ |
| latest  | :white_check_mark: |
| < latest | :x:               |

## Reporting a Vulnerability

We take security vulnerabilities seriously. To report a vulnerability:

1. **Do not open a public issue.** Public disclosure of a security vulnerability could put users at risk.
2. Submit a report through GitHub's **Security Advisories** feature:
   https://github.com/Nex-Devz/YuKumo-Docs/security/advisories/new
3. If you cannot use the advisory form, email the maintainers directly with the subject `[SECURITY]` and include as much detail as possible.

### What to include

- The affected version or commit
- A description of the vulnerability and its impact
- Steps to reproduce (or a minimal proof of concept)
- Any suggested remediation, if known

### What happens next

- **Acknowledgment** — we will acknowledge your report within 3 business days.
- **Triage** — we will investigate and confirm the issue, scope, and impact.
- **Fix & disclosure** — a fix is prepared and released, then the vulnerability is publicly disclosed with credit to the reporter.

We ask that you give us a reasonable time window to fix and release a patch before public disclosure.
